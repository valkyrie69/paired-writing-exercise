//Exercise #1

Open the Mule app, to test the components connectivity, for HTTP or FTP connector. 
Failing the test results in default log in warning message.

To change the default message, set the reconnect number.
•	Fail Deployment (failsDeployment): Exhausting reconnections leads to failed connections.
•	Reconnect (reconnect): Limits the number of reconnections attempts and the interval to execute them. 
For example, setting the count to 5 reconnections for every 4000 milliseconds (ms), results in 2 reconnection attempts at a frequency of 2000ms.


[source,xml]
----
<http:request-config name="HTTP_Request_Config" doc:name="HTTP Request Config">
  <http:request-conection host="https://jsonplaceholder.typicode.com/posts" port="80" >
    <reconnection failsDeployment="true" >
      <reconnect frequency="4000" count="5" />
    </reconnection
  </http:request-connection>
</http:request-config>
----

•	The app tries to reconnect every 4000 ms. 
Note: The default interval is 2000ms. The number of retries has no limits.
•	Example for not setting a limit for reconnection attempts is [source,xml]


* [source,xml]
----
<http:request-connection host="https://jsonplaceholder.typicode.com/posts" port="80" >
  <reconnection>
    <reconnect-forever frequency="4000" count=”5”/>
  </reconnection>
</http:request-connectio>
----
